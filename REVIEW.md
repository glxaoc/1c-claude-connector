# Что смотреть ревьюеру в 1С-коннекторе

Файл читается critic и /code-review первым. Репозиторий публичный, продукт ставят чужие компании
на свои живые базы 1С: ошибка здесь видна клиентам, а не только нам.

Формат пункта: триггер в диффе, что проверить, откуда.

1. **Только чтение.** Триггер: `method:` в `server/index.js`, новый HTTP-клиент (`fetch`, `axios`, `undici`), правки `httpGetOnce`, `httpGet`, `odataGet`. Что проверить: в 1С уходит только GET; нет `POST`, `PATCH`, `MERGE`, `DELETE`, `$batch`, `X-HTTP-Method`; нет второго пути запросов в обход `odataGet`. Откуда: шапка `server/index.js`, README («только чтение»), `manifest.json` (`long_description`), smoke разделы 2 и 6.

2. **Новый инструмент MCP.** Триггер: `server.registerTool(`. Что проверить: `annotations: { readOnlyHint: true }`; инструмент добавлен в `tools` манифеста и в README (раздел «Для разработчиков»); описание по-русски объясняет, когда звать; нет инструмента, который пишет в 1С или выполняет произвольный код. Откуда: `manifest.json` `tools`, smoke «инструменты = манифест».

3. **Путь объекта и выход за OData.** Триггер: `safePath`, разбор `object`, `baseUrl`, `autoExpand`, `params` в `odataGet`. Что проверить: запрет `?`, `#`, `://`, `..`, `\` в имени объекта не ослаблен; полный адрес в `object` обрезается до имени и не меняет хост; значения параметров кодируются `encodeURIComponent`; ключи `$filter` и другие идут без кодирования `$` (старые 1С не понимают `%24filter`). Откуда: `safePath`, комментарий в `odataGet`, suite «попытка выйти за OData», smoke раздел 4.

4. **Пароли и данные клиента в журнале.** Триггер: любой `log(`, `console.`, `process.stderr`, новые поля в тексте ошибок. Что проверить: в журнал не пишутся пароль, заголовок `Authorization`, параметры запроса (`$filter` содержит имена и ИНН клиентов), строки ответа; журнал Claude Desktop пользователи прикладывают к issue. Известное место: `log("redirect", …)` пишет полный адрес с параметрами. Откуда: `log` в `server/index.js`, `.github/ISSUE_TEMPLATE/bug_report.yml` («не вставляйте пароли и данные клиентов»), smoke раздел 6.

5. **Пароли в ответах и сообщении автору.** Триггер: `contact_author`, `check_connection`, тексты ошибок с адресом, `authorDm`. Что проверить: в ответ инструмента и в ссылку `t.me/...?text=` не попадают пароль 1С, пароль SSH, логин и адрес 1С; инструкции модели по-прежнему запрещают просить пароли в чате. Откуда: suite «обращение к автору: нет пароля…», smoke раздел 4, `instructions`.

6. **Персональные данные и 152-ФЗ.** Триггер: `PII_FIELDS`, `piiHint`, `hint(`, `HINT_GAP`, `HINT_MAX`. Что проверить: справка про ПДн остаётся фактом без обещаний «безопасно»; показывается один раз; регулярка не сужена так, что телефоны и паспорта перестают ловиться. Откуда: suite «подсказка про персональные данные…», `ref_152fz_research` Ивана.

7. **Совместимость с версиями и конфигурациями 1С.** Триггер: разбор ответа (`decodeBody`, BOM, `oneCError`, JSON или XML), `describe_object` (регулярки по `$metadata`), имена `Catalog_`, `Document_`, `AccumulationRegister_`, `Balance()`, `Turnovers()`, `SliceLast()`. Что проверить: BOM в начале ответа снимается; ошибка 1С разбирается и из JSON, и из XML; нет привязки к именам объектов УТ 11 (README обещает ERP, Бухгалтерию, КА); `$metadata` качается один раз на базу (бывает десятки МБ). Откуда: README («Проверено на УТ 11…»), suite «count с BOM», «кэш метаданных».

8. **Понятные ошибки.** Триггер: `netError`, ветки статусов в `odataGet`, новые `throw new Error`. Что проверить: пользователь получает по-русски, что исправить (белый список, http или https, имя базы, права), без стека и сырых кодов Node; `isError: true`; при нескольких базах в начале название базы. Откуда: `features/errors.md`, smoke раздел 5, suite разделы 1, 4, 5.

9. **Пределы бесплатной версии.** Триггер: `MAX_ROWS`, `PAGE_ROWS`, `MAX_TEXT`, `DEFAULT_ROWS`, `FREE_LIMITS`. Что проверить: предел за вызов согласован в коде, в описании `top`, в инструкциях модели и в README; чтение порциями не теряет и не дублирует строки (`skip`); ответ обрезается с подсказкой, а не падает. Откуда: suite «top 1000…», «top 5000…», «skip + top», коммит 7cc3520 (1.5.0).

10. **Реклама автора.** Триггер: `SERVICES`, `what_else`, `instructions` (абзац «Реклама услуг автора»), `AUTHOR_HANDLE`, `AUTHOR_CHANNEL`. Что проверить: реклама только в трёх случаях из инструкций и после ответа; в ответы с данными и ошибками не добавлена; ссылка на канал только именная (`+nOX4y5DWNl42NWIy`), ссылка в личку с готовым текстом; каждую новую ссылку открыть руками. Откуда: коммиты 77c30fa, 2094423, память Ивана «ссылки на TG-канал только именные».

11. **SSH-туннель.** Триггер: `getSsh`, `sshStream`, `parseSshTarget`, `KNOWN_HOSTS`, `writeKnown`. Что проверить: отпечаток сервера проверяется и сохраняется в `~/.1c-connector/known_hosts.json`, смена отпечатка не принимается молча; разбор «грязного» адреса (`ssh://user@host:port`, `ssh root@1.2.3.4 -p 2222`) не сломан; ключ и пароль SSH не пишутся в журнал. Откуда: suite раздел SSH (`tests/mockssh2.mjs`).

12. **Версия релиза.** Триггер: `VERSION`, `version` в `manifest.json`, `package.json`, `package-lock.json`. Что проверить: все четыре совпадают; версия поднята по смыслу (новый инструмент или поведение: minor); строка версии в `check_connection` и в шаблоне issue соответствует. Откуда: README (раздел «Перед новой версией»), smoke раздел 1.

13. **Состав пакета `.mcpb`.** Триггер: `.mcpbignore`, `package.json` `scripts.pack`, новые файлы и папки в корне. Что проверить: в пакет не попадают `tests/`, `docs/`, `.claude/`, `HANDOFF.md`, `.env`, `settings.xml`, `work/`, `dist/`; шаблоны от корня (`/tests/`), иначе выпадают одноимённые папки в `node_modules`; `clean-native` по-прежнему удаляет нативные сборки ssh2 (иначе пакет с Windows не встанет на Mac). Откуда: README («Собирать пакет нужно только через `npm run pack`…»), smoke раздел 7.

14. **Манифест и форма настроек.** Триггер: `manifest.json` `user_config`, `mcp_config.env`, `cfg(`, `readBase`. Что проверить: все пароли `sensitive: true` (хранилище ОС); каждое поле `user_config` проброшено в `env` и читается в коде; пустое необязательное поле (`${user_config.x}`) понимается как пусто; обязательные поля не добавлены без нужды (сломают обновление у тех, кто уже настроил). Откуда: `manifest.json`, `cfg` в `server/index.js`, smoke раздел 1.

15. **Зависимости.** Триггер: `package.json` `dependencies`, `package-lock.json`. Что проверить: новая зависимость оправдана и без нативной сборки (или вычищается `clean-native`); `@modelcontextprotocol/sdk` не обновлён через мажорную версию без прогона; в пакете есть `node_modules/@modelcontextprotocol/sdk/dist/esm/server/mcp.js`. Откуда: README (раздел «Перед новой версией»), smoke раздел 7.

16. **Публичный репозиторий.** Триггер: любые новые файлы, `README.md`, `docs/`, примеры адресов и выгрузок. Что проверить: нет адресов, логинов и выгрузок реальных баз клиентов, имён клиентов, ключей; в README и кейсах «ИИ-система», без названий моделей в публичных кейсах клиентов; `.gitignore` по-прежнему закрывает `settings.xml`, `.env`, `work/`. Откуда: `.gitignore`, память Ивана «Без Claude в публичных кейсах».

17. **Релиз и установщик.** Триггер: подготовка версии, `dist/`, упоминание `gh release`. Что проверить: релиз выпускает только Иван; `.mcpb` собран `npm run pack`, проверен установкой в Claude Desktop («проверь связь с 1С»); ссылка `releases/latest/download/1c-connector.mcpb` в README продолжает вести на файл с тем же именем. Откуда: README (кнопка «Скачать»), `features/release-pack.md`.

18. **Проверка перед сдачей.** Триггер: правки в `server/`, `manifest.json`, `package*.json`, `.mcpbignore`, `tests/`. Что проверить: в описании PR строка `Проверено: …` с честным списком; прогнан `bash .claude/skills/verify-1c-connector/verify.sh all` (`ALL OK`); `npm test` всегда выходит с кодом 0, смотреть строку `ИТОГО`; правки самих проверок (`.claude/skills/verify-1c-connector/`, `tests/`) не смешаны с рабочей задачей; автор коммитов Иван Дробитько, без `Co-Authored-By` и упоминаний Claude в коммитах и PR. Откуда: `.claude/skills/verify-1c-connector/SKILL.md`, общий CLAUDE.md Ивана (цикл проверки, «Claude не автор коммитов»).
