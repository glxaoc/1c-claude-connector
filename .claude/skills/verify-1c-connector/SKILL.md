# verify-1c-connector

Один вызов (около 45 с: три прогона подряд 20.11.2026 заняли 45, 43 и 46 с):

```
bash .claude/skills/verify-1c-connector/verify.sh all
```

Код 0 и строка `ALL OK` = все проверки прошли. Доказательства в
`C:/Users/xaoc/1c-connector-out/verify-evidence/<дата-время>-<sha>/`.

## Что это и чем не является

- Настоящее: `server/index.js` целиком, запущенный отдельным процессом по stdio через клиент MCP SDK
  (так его запускает Claude Desktop), HTTP-клиент коннектора, разбор ошибок, сборка `.mcpb` тем же
  `mcpb`, что в `npm run pack`, и запуск сервера уже из распакованного пакета.
- Подменено: только 1С. `smoke.mjs` поднимает OData-заглушку на `127.0.0.1` со случайным портом.
  Заглушка пишет каждый запрос (метод, путь, параметры) в `mock-requests.json`.
- Данные синтетические: пользователь `smoke.reader`, «клиент» `ООО Ромашка-Смоук`, телефон
  `+7 999 000-11-22`. Внешних адресов нет. HOME сервера во временной папке, удаляется.
- Параллельно идёт существующий набор `npm test` (`tests/run-tests.mjs`: 82 сценария, включая
  SSH-туннель на локальном SSH-сервере). Он всегда выходит с кодом 0, поэтому `verify.sh` читает
  строку `ИТОГО: N прошло, 0 упало`.

## Launch

`verify.sh` из любой папки (Git Bash на Windows):

| Команда | Что делает |
|---|---|
| `verify.sh deps` | `npm ci --ignore-scripts --prefer-offline`, если нет `node_modules` или lock новее |
| `verify.sh doctor` | только чтение: node 18+, зависимости, `mcpb` офлайн, порты тестов 8766/2224/2225 свободны |
| `verify.sh smoke` | `smoke.mjs` (42 проверки, около 20 с, из них сборка пакета около 13 с) |
| `verify.sh tests` | `node tests/run-tests.mjs` (около 48 с), временные HOME в своей папке и удаляются |
| `verify.sh all` | deps, doctor, затем smoke и tests параллельно, итог `ALL OK` / `ALL FAILED` |

`mcpb` берётся из npx-кэша (`%LOCALAPPDATA%/npm-cache/_npx/*/node_modules/@anthropic-ai/mcpb`)
или из `MCPB_CLI`. Если его нет, doctor скажет, как поставить один раз с сетью.
Два `verify.sh` параллельно не запускать: тесты репо держат фиксированные порты.

## Что доказывает smoke (по разделам `smoke.mjs`)

1. Версии: `VERSION` в `server/index.js` = `manifest.json` = `package.json` = `package-lock.json`;
   точка входа манифеста; все поля паролей `sensitive: true`.
2. Только чтение в коде: все `method:` равны `GET`, нет `fetch`/`axios`/посторонних клиентов.
3. Главный путь: старт, версия сервера, инструкции; инструменты = `tools` манифеста, у всех
   `readOnlyHint: true`, нет инструментов записи; check_connection, list_objects (несколько слов),
   describe_object (поля, табличная часть), query (select с `Контрагент/Description`, в 1С ушёл
   `$expand=Контрагент`, `$filter`, `$orderby`, `$top`), Balance() с названиями, count с BOM,
   справка про 152-ФЗ.
4. Только чтение в поведении: `../` и `?$method=DELETE` в имени объекта блокируются; полный чужой
   адрес в `object` не уводит запрос с адреса из настроек; contact_author без пароля и адреса 1С.
5. Ошибки 1С: 400 (текст 1С про фильтр), 403, 404, 500 (лицензия), HTML веб-клиента вместо JSON,
   401, 502 шлюза, закрытый порт, пустой адрес. Везде `isError`, понятный текст, без стека.
6. Итог по всем вызовам: заглушка получила только GET и только в публикацию из настроек; журнал
   сервера (stderr) без пароля, Basic-заголовка, данных клиента и значений фильтра.
7. Релиз: `mcpb validate`, `mcpb pack` копии репо с приманками (`.env`, `settings.xml`, `work/`,
   `HANDOFF.md`, `tests/hostkey1`, `dist/`, `codex/`, `*.bak-1c`), в пакете есть сервер, иконка,
   SDK, ssh2, zod; нет тестов, `.claude/`, документации и приманок; нативные модули ssh2 вычищены;
   сервер из распакованного пакета стартует и видит 1С.

Проверки ловят регресс: 20.11.2026 нарочно вернули старый `.mcpbignore`, поменяли GET на POST и
добавили в журнал адрес с заголовками: упало 21 из 42, в том числе «только GET», «журнал без
пароля» и «пакет без секретов».

## Evidence

- `meta.txt`: ветка, sha, node, незакоммиченные файлы (что реально проверено).
- `smoke.log`, `smoke-result.json`: все проверки PASS/FAIL с деталями и временем.
- `smoke-transcript.txt`: каждый вызов инструмента и ответ коннектора, как их видит Claude.
- `mock-requests.json`: все запросы, дошедшие до «1С». `server-stderr.log`: журнал коннектора.
- `1c-connector.mcpb`, `mcpb-files.txt`, `mcpb-pack.log`: собранный пакет и его состав.
- `tests.log`: полный вывод `npm test`.

## Не покрыто (и почему)

- Настоящая 1С и версии платформы: заглушка отвечает как УТ 11 по формату OData v3 1С. Другие
  конфигурации (ERP, Бухгалтерия, КА), XML-ответы ошибок старых платформ, gzip от IIS/Apache
  проверяются только глазами на живой базе.
- Claude Desktop: установка `.mcpb` двойным кликом, форма настроек, хранение паролей в Windows
  Credential Manager / macOS Keychain. Проверяется руками перед релизом.
- macOS: пакет собирается на Windows, на Mac не запускается.
- https с самоподписанным сертификатом, редирект на другой хост, таймаут 45 с: нет в smoke
  (таймаут удлинил бы прогон); часть сценариев есть в `tests/suite.mjs`.
- SSH-туннель только в `npm test` (локальный SSH-сервер на ssh2), не в smoke.
- Тест «несуществующий домен» в `tests/suite.mjs` делает DNS-запрос `no-such-host-1c.invalid`
  (зона `.invalid` зарезервирована, соединения нет). Это единственное обращение наружу.
- Публикация релиза на GitHub (`gh release`) не проверяется и не запускается.

## Helpers

- `verify.sh`: оркестрация. `smoke.mjs`: заглушка 1С, проверки, сборка пакета; код 0/1.
- `features/`: карта пользовательских путей. Новая функция или инструмент: файл в `features/`,
  шаг в `smoke.mjs`, обновить `tools` в манифесте (иначе упадёт проверка «инструменты = манифест»).
